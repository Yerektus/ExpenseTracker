I used Claude Opus 5.5 in two ways: in a chat, where it only saw my screenshots and command output, and as a coding agent inside the repository, where it had the whole codebase and AGENTS.md as context. Working on the Expense Tracker project showed me that an AI agent can speed up development, but its output cannot be taken on trust. The agent quickly generated a working full stack project, yet some of its claims did not hold up when I checked them. For example, in the chat it wrongly assumed that the API accepted a negative amount. During the risk review several findings also turned out to be wrong: the open CORS setting, the way peer dependencies work, and the command it suggested for checking a warning. On the other hand, one risk that was marked only as an assumption, an Infinity value in the amount, was actually confirmed.
My main takeaway is that evidence matters more than confident wording. I asked for real command output, checked every finding myself and classified each one as Confirmed, Plausible or Unsupported. The most valuable step was testing the tests by breaking the code on purpose: the test suite caught all 9 defects I introduced.
AGENTS.md made the agent's work more predictable. It clearly lists safe commands, forbidden actions and review gates, and new dependencies were added only after my approval. The linter we added immediately found a real problem in data loading, and we fixed it without disabling the rule.
That is why the release is conditional, and the final decision is made by a human, not by the agent.
